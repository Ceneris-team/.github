## `⚙` Reglas Básicas para Trabajar Juntos

Para mantener un ambiente de desarrollo profesional y seguro, por favor sigue estas reglas esenciales:

### `[1]` Código de Conducta
¡Trabajamos en equipo! Aquí todos somos bienvenidos:
*   **Respeto:** Valoramos cada pregunta y cada aporte. No hay preguntas tontas.
*   **Colaboración:** Ayudémonos mutuamente a crecer como desarrolladores.
*   **Inclusividad:** Todos estamos aprendiendo, sin importar nuestro nivel de experiencia.

### `[2]` Seguridad - `⚠ CRÍTICO`
Trabajamos con datos sensibles. **Sigue estas reglas siempre:**

⛔ **NUNCA SUBAS:**
*   Contraseñas, API Keys o tokens de acceso
*   Archivos `.env` con credenciales
*   Datos reales de clientes o coordenadas GPS
*   Información personal identificable (PII)
*   Certificados SSL o claves privadas

✅ **SÍ PUEDES:**
*   Usar archivos `.env.example` con valores de ejemplo
*   Subir datos sintéticos o anonimizados
*   Documentar cómo configurar variables de entorno

🚨 **Si encuentras información sensible expuesta:** Repórtala inmediatamente a `security@ceneris.com`

### `[3]` Buenas Prácticas de Desarrollo

**Para Python/Django:**
*   Sigue el estilo **PEP 8**
*   Documenta tus funciones y clases
*   Escribe commits descriptivos en español o inglés
*   Usa nombres de variables claros y significativos

**Para Git:**
*   Crea branches descriptivos: `feature/nueva-funcionalidad` o `fix/correccion-bug`
*   Haz commits pequeños y frecuentes
*   Escribe mensajes de commit claros sobre qué cambios hiciste

**Pull Requests:**
*   Describe qué hace tu código y por qué
*   Asegúrate de que el código funcione antes de crear el PR
*   Pide ayuda si tienes dudas - ¡estamos para apoyarte!
